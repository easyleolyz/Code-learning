## 004 选择、冒泡、插入排序
本节内容：

1)选择排序一句话：i~n-1范围上，找到最小值并放在i位置，然后i+1~n-1范围上继续


2)冒泡排序一句话：0~i范围上，相邻位置较大的数滚下去，最大值最终来到i位置，然后0~i-1范围上继续


3)插入排序一句话：0~i范围上已经有序，新来的数从右到左滑到不再小的位置插入，然后继续

### 1)选择排序
```java
//交换位置的代码
//传参,传入arr数组本身,才能进行交换,否则无法带出对应的结果,作用域或者是压栈的原因
public static void swap(int[] arr ,int i, int j){
    int tmp = arr[i];
    arr[i] = arr [j];
    arr[j] = tmp;
}
```
选择排序是从小到大开始排序,每一次都在找全局的最小,然后放在最前面(这个小全局的),我们要找n个最小--->所以外层循环n次

内层循环找小全局最小,因此他的比较次数为,n + n-1 + n-2,...,1,所以时间复杂度为O($n^2$)


```java
public static void selectionSort(int[] arr){
    //为什么要加这一块内容
    if (arr == null || arr.length <2){
        return;
    }
    for(int i = 0;i < arr.length-1; i++){
        int minIndex = i;
        for(int j = i;j < arr.length-1;j++){
            if(arr[j] < arr[minIndex]){
                minIndex = j;
            }
        }
        swap(arr,i,minIndex);
    }
}
```
### 2)冒泡排序

冒泡排序是每次排好一个位置,即每次排好最后最大的位置

方法是,每次都是在全局遵循"两两之间,谁大谁往右的原则",我们要找n次最大--->所以外层循环n次

内层每次两两比较为当前全局的l-1次

n-1 + n-2 + n-3,...,1,所以时间复杂度为O($n^2$)
```java
public static void bubbleSort(int[] arr){
    if (arr == null || arr.length <2){
        return;
    }
    for(int i = arr.length-1;i > 0; i--){
        //j是到不了i的位置的所以用"j < i"
        for(int j = 0;j < i; j++){
            if(arr[j] > arr[j+1]){
            swap(arr,j,j+1);
            }
        }
    }
}

```

### 3)插入排序---"三傻排序中最有用的"

左老师形容"像打扑克牌一样从大到小整理"

0~n-1;

我们每次维持局部的从小到大的有序状态

0-0

0-1

0-2

0-3···的有序直到0-n-1有序

所以外层循环对应为n个

内层循环我们,从局部的最右侧开始向左看,小于我就换位置,遍历局部,

1 + 2 + 3 +...+ n-1

```java
public static void insertionSort(int[] arr){
    if(arr == null || arr.length < 2){
        return;
    }
    for(int i = 1;i < arr.length;i++){
        for(int j = i; j > 0;j--){
            if(arr[j]<arr[j-1]){
                swap(arr,j,j-1);
            }
        }
    }
} 

```

外循环数,内循环数,交换次数,中间打断会有什么情况,时间复杂度,空间复杂度,排序的稳定性,算法的具体思想


之前的插入排序存在一定的问题

1)for (int i = 0; i < arr.length; i++)

当 i == arr.length - 1（最后一个元素）时：

内层循环只会执行一次（j 也只能等于 i）

minIndex 必然还是 i

最后执行一次 swap(arr, i, minIndex)，也就是 swap(arr, n-1, n-1)

这轮外循环对排序没有贡献，属于多余的一轮。

2)每一轮都无条件 swap

当本轮最小值本来就在位置 i（即 minIndex == i）时，就会发生：

swap(arr, i, i)（自交换）
```java
for (int i = 0; i < arr.length - 1; i++) {
    int minIndex = i;
    for (int j = i + 1; j < arr.length; j++) {
        if (arr[j] < arr[minIndex]) minIndex = j;
    }
    if (minIndex != i) {
        swap(arr, i, minIndex);
    }
}

```

插入排序好像没有注意到一些特殊可以加速的情况
想一想为什么要break
```java
public static void insertionSort(int[] arr){
    if(arr == null || arr.length < 2){
        return;
    }
    for(int i = 1;i < arr.length;i++){
        for(int j = i; j > 0;j--){
            if(arr[j]<arr[j-1]){
                swap(arr,j,j-1);
            }else{
                break;
            }
        }
    }
} 
```
当你比较到某一步发现：
```java
arr[j] >= arr[j-1]
```
意味着“当前这个元素已经不需要再向左移动了”。
因为 arr[0..j-1] 是有序的，所以：

arr[0] <= arr[1] <= ... <= arr[j-1] <= arr[j]

既然 arr[j] 已经 ≥ arr[j-1]，那它也一定 ≥ 更左边的所有元素，再往左比较没有意义，所以可以 break。
交换次数不变（该换还是会换），但比较次数大幅减少（不做无意义的扫描）


冒泡排序也可以进行一定的加速
如果某一趟（某一轮外循环）完全没有发生交换，说明数组已经有序，可以直接结束。
```java
public static void bubbleSort(int[] arr){
    if (arr == null || arr.length <2){
        return;
    }
    for(int i = arr.length-1;i > 0; i--){
        boolean swapped = false;          // 本趟是否发生交换
        //j是到不了i的位置的所以用"j < i"
        for(int j = 0;j < i; j++){
            if(arr[j] > arr[j+1]){
            swap(arr,j,j+1);
            swapped = true;
            }
        }
        if (!swapped) break;              // 本趟无交换 => 已有序
    }
}


```


| 算法               |  平均时间 |  最坏时间 |  最好时间 |   空间 | 稳定性 | 核心思想                         |
| ---------------- | ----: | ----: | ----: | ---: | --- | ---------------------------- |
| 选择排序             | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 | 每轮从未排序区选最小放到当前位置             |
| 冒泡排序（无提前退出）      | O(n²) | O(n²) | O(n²) | O(1) | 稳定  | 相邻比较交换，把最大逐步“冒”到末尾           |
| 冒泡排序（加提前退出）      | O(n²) | O(n²) |  O(n) | O(1) | 稳定  | 若一轮无交换则已排序                   |
| 插入排序（无 break） | O(n²) | O(n²) | O(n²) | O(1) | 稳定  | 扫描已排序区，靠相邻交换插入               |
| 插入排序（常见优化版）      | O(n²) | O(n²) |  O(n) | O(1) | 稳定  | 遇到不需要移动时提前停止；或用“移动”代替多次 swap |


如果这几个排序中间被打断会发生什么？

1)选择排序,arr[0..k-1] 是全局最小的 k 个元素，并且已经按升序排好

arr[k..n-1] 仍然是未排序区（内部顺序不保证）

2)冒泡排序,最右侧 t 个位置（数组末尾那一段）已经是全局最大的 t 个元素，并且有序。

左侧剩余部分未必有序。

3)插入排序,arr[0..k] 一定是有序的（这是插入排序最核心的性质）

arr[k+1..n-1] 仍是未处理部分

**与选择/冒泡不同：插入排序在中途保证的是“已排序前缀有序”，但并不保证它是“全局最小的 k+1 个元素”（不过最终会变成全局有序）。**


为什么选择排序不稳定

选择排序每轮会把“最小元素”与 i 位置交换。
这个交换可能把某个相等元素跨越到另一个相等元素的前面，从而打乱它们的相对顺序。

  - 重要补充：即使你的比较条件是 < 而不是 <=，选择排序仍然可能不稳定，因为不稳定来自“交换带来的跨越”，不是来自“如何选择相等元素”。




**关于交换次序的一些思考,为什么冒泡和插入排序的交换次数总相同,以及通常选择排序的交换次数为什么通常更少,**

冒泡排序每次交换相邻逆序对，每次交换都会让逆序对数量减少 1

相邻交换版插入排序也一样，每次把当前元素向左交换一位，本质也是消掉一个逆序对

最终要排成有序，必须把逆序对清零，所以两者交换次数都等于该数组的逆序对数量

对 5 3 1 2 4，逆序对一共 6 个，所以冒泡/插入都为 6


选择排序每一轮最多交换一次（把最小值直接换到位），因此：

交换次数 ≤ n-1

很多时候明显少于冒泡/插入的“逆序对次数”

但它的交换是“远距离交换”，会导致：

可能把相同元素的相对顺序打乱 ⇒ 不稳定

==逆序对是什么（Inversion）==

给定数组 arr[0..n-1]，如果存在一对下标 i < j，但值却满足：

arr[i] > arr[j]

那么 (i, j) 就叫一个逆序对。
**一次相邻交换只会影响与这两个元素相关的逆序关系**

**关于内外层次数的一些想法**

统计口径:

cnt_i 理解为：外层循环实际执行了多少“趟”

cnt_j 理解为：关键比较次数（也就是每次进入内层循环体后执行一次 if 判断的次数）

cnt_swap 理解为：真正发生交换的次数


选择排序

外层：恒为 n-1

内层比较：恒为 n(n-1)/2（与输入无关）

交换：0 ~ (n-1)

冒泡（提前退出）

外层：1 ~ (n-1)（越有序越小）

内层比较：(n-1) ~ n(n-1)/2

交换：等于逆序对数

插入（有 break，相邻交换版）

外层：恒为 n-1

内层比较：(n-1) ~ n(n-1)/2（越有序越小）

交换：等于逆序对数

1) 逆序对再明确一次

逆序对：存在 p < q 且 arr[p] > arr[q]，则 (p,q) 是一个逆序对。逆序对总数记为 Inv(arr)。

2) 看选择排序某一趟交换到底交换了什么

在第 i 趟：

m = minIndex（m > i）

y = arr[m] 是 arr[i..n-1] 里的最小值

x = arr[i]

因为要交换，必有 y < x

交换前：... x ... y ...（x 在 i，y 在 m）
交换后：... y ... x ...

3) 关键观察：交换只会影响区间 [i, m] 内相关的逆序对

对于 区间外的元素：

左边 t < i：它永远在 x,y 左边，交换只是在 i 和 m 之间互换值，不会改变它与 {x,y} 形成逆序对的“总数”

右边 t > m：它永远在 x,y 右边，同理不改变“总数”

因此，逆序对变化只需要看 夹在中间的元素 k ∈ (i, m)。

4) 证明“逆序对至少减少 1”

交换前，至少有 1 个逆序对：

因为 i < m 且 x > y，所以 (i, m) 一定是逆序对（贡献 1）

交换后，这个逆序对消失：

变成 y 在左、x 在右且 y < x，所以 (i,m) 不再是逆序对

接下来要担心的是：会不会因为交换而“新增”了同样多的逆序对，把这 1 抵消掉？

看中间每个元素 z = arr[k]（i < k < m）：

因为 y 是后缀最小值，所以对所有这些 z 都有：

y ≤ z

于是交换后：

(i, k) 这种逆序对永远不可能出现（因为左边是 y，y 不可能 > z）

同时，交换前 (k, m) 这种逆序对通常是存在的（只要 z > y 就算），交换后变成 (k, m) 是否逆序取决于 z > x。由于 x > y，满足 z > x 的情况不会比满足 z > y 的情况更多（更苛刻），因此这部分逆序对数量不会“净增加”到抵消掉前面消失的 (i,m)。

更形式化一点，你可以把每个中间元素 z 的贡献列出来，会得到：

对每个 z，交换带来的逆序对变化 ≤ 0

再加上 (i,m) 这个必然减少的 1
⇒ 总变化 ≤ -1

所以：

每发生一次选择排序的交换，逆序对总数至少减少 1。

4) 你说的“不是相邻交换，所以逆序数可能增或减很多”对吗？

相邻交换：每交换一次，逆序对数一定恰好减少 1（这是为什么冒泡/相邻插入交换次数=逆序对数）。

非相邻交换（选择排序）：一次交换会同时影响很多对元素的相对关系，所以逆序对数可能减少很多，也可能局部增加一些，净变化不固定。

但由于选择排序每次把“当前后缀最小值”放到前面，总体趋势是快速减少混乱，最终逆序对变为 0。
